# Go 工程能力学习总计划

## 背景与当前起点

- 目前每天约 1.5 小时做 Java 算法题，另约 1.5 小时用于工程代码训练。
- 算法题能够使用 Java 完成，但 Go 基础语法已经遗忘，需要先快速唤醒。
- 已经接触过分布式存储、数据库和线上问题，但独立从需求开始组织工程代码的能力需要系统补齐。
- AI 可以作为讲解、提示、调试和 Review 工具，但不能替代第一版实现和最终理解。

## 学习目标

通过一系列小型、可运行、可测试的 Go Demo，逐步获得以下能力：

1. 能独立写出基本 Go 程序、package 和函数。
2. 能用 struct、method、interface 和组合组织代码。
3. 能处理错误、资源释放、文件 IO、JSON 和测试。
4. 能理解并实现 goroutine、channel、锁、任务队列、取消和优雅关闭。
5. 能写简单的 HTTP 服务，并处理超时、重试和故障。
6. 能阅读、修改和验证小型工程代码，而不是只会完成算法题。

## 学习方式

- 前 4 天作为 Go 语法唤醒期，不要求直接写线程池或大型工程。
- 之后每个 Demo 通常用 2–3 天：需求理解、分步实现、测试、增加需求、重构和复盘。
- 每次只引入一个主要新概念，优先使用标准库。
- 助教先解释小片段，再让学习者仿写或补充方法；没有尝试前不直接给完整答案。
- 允许查语法和 API 文档，但每段代码必须能被学习者解释、修改并重新运行。
- 每周结束时进行一次从空文件重写或需求变更，检验是否真正掌握。

## 能力路线

### 阶段 0：Go 基础唤醒

程序结构、import、输入输出、变量、类型、控制流、函数、多返回值、slice、map、struct、method、error、interface、package 和基础测试工具。

### 阶段 1：小型工程结构

内存存储、接口边界、错误处理、文件 IO、JSON、测试、调试和简单命令行程序。

### 阶段 2：并发与生命周期

goroutine、channel、select、Mutex、WaitGroup、原子操作、context、worker pool、限流、超时和优雅关闭。

### 阶段 3：服务与可靠性

HTTP 服务/客户端、配置、日志、重试、故障注入、回归测试和线上问题模拟。

## 记录约定

- 本 Trellis 总任务只记录长期目标、能力路线和关键记忆；学习者不需要查看 Trellis 的任务树。
- 学习者可见的每周计划、每日计划、练习说明和代码，统一放在仓库根目录的 `go_XX_xxx/` 文件夹中。
- 每个学习文件夹至少包含一个 `README.md` 和可运行的 Go 代码；如果需要测试，再在同一文件夹中添加 `_test.go` 文件。
- README 记录当天目标、检查点、运行命令、完成清单和复盘入口；Go 文件保留学习者的真实练习过程。
- 重要的长期经验同步到 `.trellis/workspace/` 日志或 `.trellis/spec/go/`，供后续课程复用。

## 完成标准

- 能在没有完整代码答案的情况下，从需求写出小型 Go 组件的第一版。
- 能为正常、失败、边界和生命周期场景补测试。
- 能解释关键数据结构、错误路径、资源所有权和并发退出条件。
- 能审查 AI 生成的代码，发现明显的逻辑、资源和并发问题。
